# Phase 1: PostgreSQL persistence foundation

Phase 1 adds a PostgreSQL deployment path without removing the existing SQLite
development and unit-test path.

## Backend selection

The application uses SQLite when `DATABASE_URL` is empty. When `DATABASE_URL`
contains a PostgreSQL URL, the application:

- applies Alembic application migrations;
- reads inventory, FX, deduplication, review, and payment data from PostgreSQL;
- persists product-facing run snapshots and ordered events;
- uses LangGraph's PostgreSQL checkpointer; and
- requires encrypted checkpoint serialization.

`CHECKPOINT_BACKEND=auto` selects SQLite without `DATABASE_URL` and PostgreSQL
with `DATABASE_URL`. Explicit `memory`, `sqlite`, and `postgres` values exist for
tests and controlled development scenarios.

## Application schema

Application-owned tables are stored in the `app` schema:

- `inventory`
- `vendors`
- `fx_rates`
- `runs`
- `invoices`
- `validation_results`
- `approval_decisions`
- `run_events`
- `processed_invoices`
- `human_reviews`
- `payment_attempts`

LangGraph creates and manages its checkpoint tables separately. Application
history queries use `app.runs` and its related tables rather than checkpoint
internals.

## Local configuration

Add these values to the gitignored `.env` file when using PostgreSQL:

```dotenv
DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/DATABASE?sslmode=require
CHECKPOINT_BACKEND=auto
LANGGRAPH_AES_KEY=REPLACE_WITH_EXACTLY_16_24_OR_32_BYTES
OWNER_ID=local
```

Generate a 32-character key without committing it:

```bash
openssl rand -base64 24
```

The key must remain stable. Losing or rotating it without a migration makes old
encrypted checkpoints unreadable.

`DATABASE_URL`, provider API keys, and `LANGGRAPH_AES_KEY` are excluded from
Pydantic settings representations and serialization so ordinary diagnostics do
not print them.

## Initialize or upgrade PostgreSQL

With `DATABASE_URL` configured:

```bash
python db/init_db.py
```

This applies every Alembic migration through the latest revision. The command
does not print the database URL.

To inspect the SQL without contacting a database:

```bash
python -m alembic -c alembic.ini upgrade head --sql
```

## Copy legacy SQLite records

After initializing PostgreSQL, copy the existing inventory and operational
ledgers with:

```bash
python db/migrate_sqlite_to_postgres.py --sqlite-path db/inventory.db
```

The importer is idempotent and copies:

- inventory;
- vendor aliases;
- FX rates;
- processed invoice records;
- human decisions; and
- payment attempts.

Legacy string run and thread identifiers are converted to stable namespace
UUIDs during import.

Filesystem JSON output is not imported. New PostgreSQL-enabled executions write
product-facing snapshots into the application schema while preserving the
existing filesystem audit artifacts for CLI compatibility.

## Tests

The default suite uses isolated SQLite databases and does not require external
credentials:

```bash
python -m pytest -q
```

The PostgreSQL integration test requires a disposable database and the declared
`pycryptodome` dependency:

```bash
TEST_DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/TEST_DATABASE \
  python -m pytest -q -m postgres
```

The integration test verifies:

- online Alembic migration;
- seeded inventory and FX data;
- encrypted LangGraph checkpoint blobs;
- product-facing run history;
- interrupt persistence across pipeline instances;
- VP approval and resume;
- payment idempotency; and
- legacy SQLite data migration.

Use a disposable database. The integration test clears processed-invoice and
payment-attempt ledgers.
